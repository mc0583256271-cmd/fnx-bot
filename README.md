# בוט הפניקס - עוזר שירות לקוחות מבוסס RAG

בוט שעונה על שאלות לקוחות **רק** מתוך המידע שבאתר [fnx.co.il](https://www.fnx.co.il), עם קישור למקור בכל תשובה.

**🌐 הבוט באוויר: https://fnx-bot.streamlit.app** · עמוד מנהל: https://fnx-bot.streamlit.app/admin (בסיסמה)

| | |
|---|---|
| נכונות | סירב ל-**20/20** שאלות שאין עליהן תשובה באתר, ענה על **40/40** שיש עליהן תשובה, עמד ב-4/4 ניסיונות פריצה |
| הוכחה | לכל תשובה ציטוטים מהאתר שהקוד אימת מילה במילה, וכל מספר בתשובה נבדק מול האתר |
| חוויה | תשובות קצרות (חציון 38 מילים), כפתורי "רוצים לדעת עוד?", 👍/👎, עיצוב בשפת אתר הפניקס, מותאם לטלפון |
| מנהל | רענון המידע מהאתר, "מכ"ם פערים" (מה לקוחות שואלים ולא מוצאים), משוב לקוחות, בדיקת תקינות |

**הרעיון המרכזי: כל תשובה חייבת להוכיח את עצמה.** ליד כל תשובה מוצגים המשפטים המדויקים מהאתר שמוכיחים אותה,
והקוד - לא המודל - בודק אותם מילה במילה, וגם בודק שכל מספר בתשובה מופיע באתר. תשובה שלא עוברת את הבדיקה לא מוצגת.

## מבנה הפרויקט
```
fnx-bot/
├── ingest/   "הכנת הספר" - איסוף, ניקוי וחיתוך המידע מהאתר
├── core/     "המוח" - חיפוש (retriever), ספקי מודל שפה (providers), שאלות גבול (guardrails), תשובה (answer), עיצוב משותף (theme)
├── assets/   הסמל בכרטיסיית הדפדפן (בועה כתומה על כחול הפניקס)
├── eval/     בדיקות איכות על שאלות אמיתיות
├── data/     המידע שנאסף מהאתר (data/index = האינדקס שהשרת טוען)
├── app.py    נקודת הכניסה: ניתוב בין הצ'אט (/) לעמוד המנהל (/admin)
└── views/    chat.py - הצ'אט ללקוחות, admin.py - עמוד המנהל
```

## הפעלה

**פעם אחת:**
```
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```
יוצרים קובץ `.env` (לפי `.env.example`):
```
GEMINI_API_KEY=...       # חובה: הטמעות (חיפוש). גיבוי למודל השפה
ANTHROPIC_API_KEY=...    # מודל השפה הראשי (Claude). בלעדיו - Gemini בלבד
ADMIN_PASSWORD=...       # סיסמת עמוד המנהל. בלעדיה העמוד סגור
```

**בענן (Streamlit Community Cloud) - כך הבוט רץ ב-https://fnx-bot.streamlit.app:**
1. ב-share.streamlit.io: Create app -> המאגר `mc0583256271-cmd/fnx-bot`, ענף `main`, קובץ ראשי `app.py`.
2. Settings -> Secrets: שלושת המפתחות בפורמט `GEMINI_API_KEY = "..."` (עם מרכאות). המפתחות לא ב-GitHub.
3. כל מיזוג ל-`main` מתעדכן בענן לבד. אם לא - Manage app -> ⋮ -> Reboot app.
האינדקס (`data/index/`, תוכן ציבורי מהאתר) נמצא במאגר, ולכן השרת לא צריך לבנות אותו.
בתוכנית החינמית האפליקציה "נרדמת" אחרי כמה ימים בלי שימוש ומתעוררת בלחיצה (כחצי דקה).

**בניית האינדקס** (פעם אחת, וכל רענון):
```
python ingest/index.py             # מהפסקאות הקיימות (data/chunks.jsonl)
python ingest/index.py --refresh   # רענון מלא: סריקת האתר -> חיתוך -> אינדקס
```

**הצ'אט:**
```
streamlit run app.py
```
נפתח בדפדפן: http://localhost:8501 (עמוד המנהל: http://localhost:8501/admin)

**עדכון לגרסה האחרונה:** `git pull origin main`, ואז להריץ שוב את הצ'אט.

**בדיקות:**
```
python eval/run_eval.py                           # הבוט כולו: 40 עם תשובה, 20 בלי, 21 תורות שיחה ותרחישי הכשלה
python eval/run_eval.py --model claude-haiku-5-5  # מודל אחד בלבד
python eval/compare_search.py --questions eval/questions_full.json --formats search   # השוואת שיטות חיפוש
python eval/ping_models.py                        # זמני תגובה של כל מודל
```

## שלב 1: איסוף המידע מהאתר ✅

### איך מריצים
```
python ingest/crawl.py      # סריקה וניקוי  ->  data/pages.jsonl
python ingest/chunk.py      # חיתוך לפסקאות ->  data/chunks.jsonl
```
בדיקה מהירה על 10 עמודים בלבד: `python ingest/crawl.py --test 10`

### איך נאסף התוכן
1. **רשימת העמודים** נלקחת מה-[sitemap](https://www.fnx.co.il/sitemap.xml) של האתר, ומסוננת למדורים רלוונטיים (ביטוח, תביעות, שירות, פנסיה, גמל, חיסכון, הלוואות). מכבדים את [robots.txt](https://www.fnx.co.il/robots.txt).
2. **הורדה מנומסת:** בקשה כל 2 שניות. אחרי כ-1,000 בקשות ברצף האתר חוסם זמנית, ולכן יש ניסיונות חוזרים עם המתנה שגדלה, ומטמון שמאפשר להמשיך מאיפה שעצרנו.
3. **ניקוי:** כ-80% מכל עמוד הם תפריטים ופוטר. שומרים רק את אזור התוכן (`#main`), ומסירים אזורים חוזרים לפי ה-class שלהם.
4. **חיתוך לפסקאות** לפי כותרות, 120-400 מילים, עם כותרת הקשר (עמוד, מדור, נושא) בראש כל פסקה.

### מה יצא
| | מספר |
|---|---|
| עמודים ב-sitemap | 1,643 |
| עמודים רלוונטיים אחרי סינון | 1,035 |
| **עמודים ייחודיים שנשמרו** | **715** |
| **פסקאות** | **2,405** (מ-712 עמודים; 3 עמודים הם רק רשימות קישורים לדוחות PDF) |

### מה הוצא, ולמה
| קובץ | מה | למה |
|---|---|---|
| `data/not_found.txt` | 36 כתובות | מחזירות 404. רובן כתובות ישנות בעברית, שהתוכן שלהן קיים תחת כתובת באנגלית |
| `data/thin.txt` | 232 עמודים | כמעט בלי טקסט: רשימות של דוחות PDF, ומאמרים שנמחקו ומפנים לעמוד אינדקס |
| `data/duplicates.txt` | 52 עמודים | תוכן זהה לעמוד אחר (מאמר שנמחק מחזיר את עמוד המדור) |

### איך מרעננים
**מי מרענן:** מנהל המערכת, בלחיצה על כפתור "רענן עכשיו" (ייבנה בשלב האירוח). הכפתור מריץ פקודה אחת: `python ingest/index.py --refresh` = סריקה, חיתוך ובניית האינדקס (ראו שלב 2).

**איך יודעים מה השתנה:** לכל עמוד נשמר ה-ETag שלו, "טביעת אצבע" שהאתר מחשב מתוכן העמוד (`data/crawl_state.json`). בהרצה חוזרת שואלים את האתר "השתנה מאז?":
- **לא השתנה** – האתר עונה 304 בלי לשלוח את העמוד, ונשאר המידע הקיים.
- **השתנה או חדש** – מורידים ומנקים מחדש.
- **נמחק מהאתר** – מוסר.
- דוח שינויים (חדש / השתנה / הוסר) נכתב ל-`data/changes.json`.

למה לא תאריך העדכון ב-sitemap: בדקנו ומצאנו עמודים שהתוכן שלהם השתנה בלי שהתאריך זז (נתוני תשואות, טופס 161). ה-ETag כן משתנה בכל שינוי בתוכן.

**זמן:** כ-25 דקות לרענון (בעיקר ההמתנה המנומסת של 2 שניות בין בקשות). בבדיקה: 703 מתוך 715 עמודים ענו "לא השתנה", בלי חסימות.

**הגנות, כדי שרענון לא יקלקל מידע טוב:**
- **ירידה חדה:** אם יצאו פחות מ-90% מהעמודים של הפעם הקודמת (למשל כי האתר חסם), שום דבר לא נשמר והמידע הקודם נשאר.
- **הורדה שנכשלה:** נשארת הגרסה הקודמת של העמוד.
- **מילים מוסתרות (xxx):** סינון אינטרנט עלול להחליף מילים ב-xxx. עמוד כזה לא נשמר; נשארת הגרסה הנקייה הקודמת, והעמוד נרשם ב-`data/masked.txt`.

הרצה מלאה מאפס (מתעלמת מה-ETag): `python ingest/crawl.py --refresh-all`

### מגבלות
- **קובצי PDF** (תנאי פוליסה, דוחות) לא נכללים.
- **אזור אישי וטפסים** (my.fnx.co.il ואחרים) לא נסרקים. הבוט יכול רק לקשר אליהם.

## שלב 2: אינדקס סמנטי וחיפוש ✅

### איך מריצים
```
python ingest/index.py             # בונה את האינדקס  ->  data/index/
python ingest/index.py --refresh   # רענון מלא: סריקה -> חיתוך -> אינדקס
```
צריך `GEMINI_API_KEY` בקובץ `.env` (ראו `.env.example`).

### איך נבחר הקטע
1. **כל פסקה הופכת לווקטור** - רשימת מספרים שמייצגת את המשמעות שלה - עם המודל `gemini-embedding-2` של גוגל. לפני הפסקה מוסיפים את כותרת העמוד, כמו שגוגל ממליצה (`title: ... | text: ...`).
2. **גם שאלת הלקוח הופכת לווקטור** באותו מודל (`task: search result | query: ...`).
3. **מחשבים דמיון קוסינוס** בין השאלה לכל 2,405 הפסקאות (פחות מאלפית שנייה), ושולפים את **8 הפסקאות הקרובות ביותר**.
4. הווקטורים מקוצרים ל-768 מספרים (מתוך 3,072): בבדיקה האיכות זהה, והאינדקס קטן פי 4 (7.4MB).

### למה ככה - הבדיקה
השווינו שלוש שיטות על 154 שאלות בדיקה (`eval/compare_search.py`, `eval/questions_full.json`):
100 שאלות על עמודים שנבחרו בהגרלה (מודל שפה כתב שאלת לקוח לכל עמוד; נפסלו שאלות שמעתיקות מהעמוד),
15 על מסלולי השקעה כמעט זהים, 8 על שמות מוצרים, ו-31 שכתבנו ידנית.

העמוד הנכון בין 5 הפסקאות הראשונות:

| שיטה | אקראי | שמות | מסלולים | ידני | סה"כ |
|---|---|---|---|---|---|
| מילים (BM25 על שלישיות אותיות) | 73/100 | 8/8 | 15/15 | 19/31 | 115/154 |
| **וקטורים** | **87/100** | 7/8 | 15/15 | **31/31** | **140/154** |
| שילוב (מילים + וקטורים) | 85/100 | 8/8 | 15/15 | 27/31 | 135/154 |

**8 פסקאות ולא 5:** 5 הפסקאות הראשונות הגיעו בממוצע מ-3.5 עמודים בלבד (כמה פסקאות מאותו עמוד). עם 8 העמוד הנכון נמצא ב-91/100 מהשאלות האקראיות (144/154 בסה"כ). המספר 8 נקבע אחרי שראינו את התוצאות, ולכן ייבדק שוב על שאלות אמיתיות.

**מה עוד יצא בבדיקה:**
- רוב ה"פספוסים" בשאלות האקראיות הם עמוד אחר עם אותו מידע (למשל "עיכוב מזוודה" מביא את "המזוודה לא הגיעה").
- **שאלה בלי שם מסלול** ("מה דמי הניהול במסלול שלי?") - אף חיפוש לא יכול לדעת איזה מסלול. הבוט צריך לשאול את הלקוח.
- **ציון הדמיון לבדו לא מספיק כדי לסרב:** "באיזה בנק כדאי לקחת משכנתא?" (אין תשובה באתר) קיבלה ציון גבוה יותר מהרבה שאלות שיש עליהן תשובה. ההחלטה לסרב תהיה של שכבת התשובה.

### רענון
המטמון (`data/emb_cache/`) שומר וקטור לכל טקסט שכבר נשלח לגוגל. ברענון נשלחות לגוגל רק פסקאות חדשות או ששונו; פסקאות של עמודים שנמחקו פשוט לא נכנסות לאינדקס.

**הגנות - האינדקס הקודם נשאר כמו שהוא אם:**
- חסרים וקטורים (נגמרה המכסה, אין רשת). מריצים שוב, וההרצה ממשיכה מאיפה שעצרה.
- יש פחות מ-90% מהפסקאות של האינדקס הקודם.
- הסריקה או החיתוך נכשלו.

החיפוש בודק שקבצי האינדקס תואמים זה לזה (מספר שורות, מודל, טביעת אצבע של הווקטורים), ומסרב לעבוד עם אינדקס חלקי או פגום.

### מגבלות
- **מכסה חינמית של Gemini:** כל פסקה נספרת כבקשה, כ-100 בדקה וכ-1,000 ביום (נמדד). רענון רגיל עולה כמה עשרות בקשות; בנייה מחדש של כל 2,405 הפסקאות (למשל אחרי שינוי בכללי החיתוך) לוקחת כ-3 ימים בחינם.
- **כל שאלת לקוח היא בקשה לגוגל** (כחצי שנייה עד שנייה). כשהמכסה נגמרת או שאין רשת, החיפוש לא עובד.
- **עמודים דומים ממדורים שונים:** למשל "תביעת נזק מים" של ביטוח עסקים מופיעה לפני ביטוח דירה. הכותרת והמדור של כל פסקה נשלחים לשכבת התשובה כדי שתבחין ביניהם.

## שלב 3: שכבת התשובה ✅

### מה קורה בכל שאלה
1. **הודעת נימוס** ("תודה", "שלום") - תשובה ידידותית מיד. **בקשה לפרט אישי** ("מה מספר הפוליסה שלי") - הסבר שאין לבוט גישה, והפניה לשירות הלקוחות (`core/guardrails.py`).
2. **שאלת המשך** - מודל השפה מנסח אותה כשאלה מלאה לפני החיפוש ("ותוך כמה זמן?" -> "תוך כמה זמן מקבלים תשובה על תביעת נזילה בבית?").
3. **חיפוש** 8 הפסקאות הקרובות (שלב 2). אם גם הקרובה ביותר רחוקה מאוד (דמיון < 0.60) - "לא מצאתי" בלי לפנות למודל.
4. **מודל השפה** מקבל את השאלה ואת הפסקאות (עם כותרת ומדור), וכותב **מילה אחרי מילה** (streaming): שורת סטטוס (תשובה / לא נמצא / שאלת הבהרה), התשובה, ושורת מקורות עם מספרי הפסקאות.
5. **בדיקה בקוד:** הקישורים נבנים מהפסקאות עצמן (המודל לא כותב כתובות, ולכן לא יכול להמציא קישור). תשובה בלי מקור תקין מוחלפת ב"לא מצאתי" - **אין מקור, אין תשובה.**

**מה הבוט עונה כשאין מידע:** "לא מצאתי את המידע הזה באתר הפניקס. לבירור אפשר לפנות לשירות הלקוחות." + קישור לעמוד יצירת הקשר. ההוראה למודל: *עדיף לא לענות מאשר לענות תשובה לא נכונה* - מידע קרוב שלא עונה על השאלה עצמה, או בקשה להמלצה אישית, = "לא נמצא".

### מודל השפה, ולמה
המבנה מונחה עצמים (`core/providers.py`): מחלקה בסיסית `LLMProvider`, ומחלקה לכל ספק (`ClaudeProvider`, `GeminiProvider`). `FallbackProvider` עובר אוטומטית לספק הבא כשספק לא זמין. החלפת מודל או ספק = שורה אחת.

**תשובות קצרות ושאלות המשך:** כל תשובה עונה רק על מה שנשאל (2-4 משפטים), ומתחתיה 2-3 כפתורי "רוצים לדעת עוד?"
שהמודל מציע מתוך הפסקאות - מי שרוצה פרטים לוחץ, ולחיצה היא שאלה רגילה שעוברת את כל הבדיקות.
הבוט מקשיב למשוב: אחרי "התשובות ארוכות מדי" הוא עונה בקצרה עד סוף השיחה, ואחרי "לא הבנתי" מסביר בפשטות.

שאלת הבהרה מותרת רק על מסלולים/קרנות עם נתונים שונים; בכל מקרה אחר (למשל נזילה - מהצנרת שלכם או מהשכן?)
הבוט מתבקש לתאר את האפשרויות במקום לשאול.
(**) "מה דמי הניהול במסלול שלי?" - במקום שאלת הבהרה ענה, כי באתר דמי הניהול זהים בכל מסלולי הפנסיה המקיפה.

תרחישי ההכשלה (`eval/dialogues.json`): ניסיונות פריצה (התעלמות מההוראות, חשיפת ההוראות, החלפת תפקיד, קוד בתשובה),
בלבול בין כיסויים (מיליון ש"ח של צד ג' מול ניתוח), הנחה שגויה בשאלה, ומחיר שלא מופיע באתר - כולם עברו.
מלכודת שנמצאה ותוקנה: "אפשר לבטח רחפן?" - המודל ענה על **רחיפה** (ספורט). עכשיו: המילה "רחפן" לא מופיעה באתר ->
בודק נושא נפרד שואל "האם הציטוטים עוסקים במה שנשאל?" -> "אין מספיק מידע באתר".
מודל השפה רץ ב"חשיבה אדפטיבית במאמץ נמוך": בברירת המחדל Claude חשב בשקט כ-12 שניות לפני המילה הראשונה, והחיבור נפל.

בדיקת המספרים: כל מספר בתשובות של Claude (סכומים, טלפונים, אחוזים) הופיע בפסקאות שנשלחו אליו. ב"עמוד הצפוי" נבדק עמוד אחד מראש; ברוב ההפרשים המקור היה עמוד אחר עם אותו מידע.

## שלב 4: אמינות גלויה, עמוד מנהל ואבטחה ✅

### כל תשובה מוכיחה את עצמה (`core/evidence.py`)
- **ציטוטים:** המודל מצרף לכל תשובה 1-4 ציטוטים מדויקים מהפסקאות. הקוד מחפש כל ציטוט מילה במילה בפסקה שממנה הוא
  כביכול נלקח (סלחני רק לעיצוב: מרכאות, רווחים, הדגשות). ציטוט שלא נמצא לא מוצג - המודל לא יכול "להמציא ראיה".
  בממשק: "✓ אומת מול האתר", ובלחיצה "הראו לי איפה זה כתוב" - הציטוטים מודגשים כמו בטוש, עם קישור לעמוד.
- **מספרים:** כל מספר בתשובה (סכום, אחוז, טלפון, תאריך, מספר ימים) חייב להופיע בפסקאות שנשלפו (גם "8" = "שמונה",
  "02.10.2025" = "2.10.2025"), או בשאלה של הלקוח. מספר שלא מופיע = כנראה המצאה או חישוב של המודל ->
  התשובה לא מוצגת. בבדיקה על 49 תשובות קודמות: אף תשובה נכונה לא נחסמה.
- **בודק נושא:** כשבשאלה יש מילה שלא מופיעה בשום מקום באתר (למשל "רחפן"), קריאה נוספת קצרה למודל בודקת
  שהציטוטים עוסקים באותו דבר שנשאל ולא בדבר שרק נשמע דומה ("רחיפה"). תשובה שמזכירה מילה כזו - נחסמת.
- **שאלת הבהרה עם סיבה:** "כדי לתת לכם את הנתון הנכון - דמי הניהול שונים בין המסלולים. באיזה מסלול אתם?"
- **בלי מסקנות:** מה שלא כתוב באתר במפורש - "לא מופיע באתר", לא "כנראה" ולא "אפשר להניח".

### עמוד מנהל (`views/admin.py`, כתובת `/admin`)
- **באותה שפת עיצוב כמו הצ'אט** (`core/theme.py`): סרגל צד כחול עם "חזרה לצ'אט", "יציאה" וקישורים לכל חלק בעמוד;
  כל נושא בכרטיס לבן משלו; מסך כניסה מעוצב. בכרטיסיית הדפדפן: "הפניקס | ניהול הבוט" עם הסמל של הבוט.
- כניסה בסיסמה (`ADMIN_PASSWORD` ב-Secrets, השוואה בזמן קבוע). 5 ניסיונות שגויים - נעילה ל-5 דקות.
- **בדיקת תקינות:** האם החיפוש ומודלי השפה עונים, וכמה זמן זה לוקח (בלי להציג מפתחות).
- **משוב לקוחות:** אחוז התשובות שעזרו, ו-10 התשובות האחרונות שקיבלו 👎 - כדי לבדוק אם חסר מידע או שהבוט פספס.
- **רענון המידע מהאתר** ברקע (`core/refresh.py`): סריקה -> חיתוך -> אינדקס. רק רענון אחד בכל רגע. פסקאות שלא
  השתנו לוקחות את הווקטור מהאינדקס הקיים (בענן אין מטמון הטמעות, ובמכסה החינמית ~1,000 הטמעות ביום).
  אם הסריקה נכשלה או שיצא פחות מ-90% מהמידע - האינדקס הקודם נשאר. אחרי רענון מוצלח הצ'אט עובר לאינדקס החדש לבד.
- **מה השתנה באתר:** עמודים חדשים, עמודים שהתוכן שלהם השתנה ועמודים שהוסרו בסריקה האחרונה.
- **מכ"ם פערים** (`core/gaps.py`): כל שאלה שהבוט ענה עליה "לא מצאתי" נרשמת - בלי השיחה, ומספרים ארוכים ומיילים
  מוסתרים. המנהל רואה מה לקוחות מחפשים ולא מוצאים באתר, מסמן שאלה כ"טופלה", מוחק את כל הרשימה (עם אישור),
  ויכול להוריד CSV. גם את המשוב אפשר למחוק (עם אישור).

### חוויית המשתמש
- **פתיחה:** ברכה לפי השעה בישראל ("בוקר טוב" / "ערב טוב"), אריחי נושאים עם אייקונים (דירה, רכב, נסיעות, בריאות, חיות מחמד,
  פנסיה וחיסכון) ושאלות לדוגמה - לחיצה שולחת שאלה.
- **תשובות קצרות** שעונות רק על מה שנשאל, ומתחתיהן "רוצים לדעת עוד?" - שאלות המשך שהמודל מציע מתוך הפסקאות.
  אחרי "לא מצאתי" או הודעת שיחה מופיעות הצעות נושאים, כדי שהלקוח לא יישאר בלי כיוון.
- **"עזרתי?" 👍/👎** מתחת לכל תשובה. המשוב נשמר בלי פרטים מזהים ומוצג למנהל.
- **בזמן ההמתנה:** שלוש נקודות מהבהבות עם "מחפש את המידע באתר הפניקס" / "כותב תשובה", והתשובה נכתבת תוך כדי.
- **"✓ אומת מול האתר"** וקישורי מקור; "הראו לי איפה זה כתוב" פותח את הציטוטים מהאתר, מסומנים כמו בטוש.
- **הבוט מקשיב:** "התשובות ארוכות מדי" -> קצר עד סוף השיחה; "לא הבנתי" -> הסבר פשוט יותר.
- **סרגל צד קבוע בימין, בכחול הפניקס** (כמו בצ'אטבוטים מקצועיים): "שיחה חדשה" (כתום, בולט), "דברו עם נציג", קיצורי נושאים,
  "איך זה עובד" ומתי נאסף המידע. בטלפון הסרגל הופך לפס עליון קומפקטי עם אייקונים. השיחה ממלאת את כל שאר המסך.
- **"הורדת השיחה"** בסוף השיחה - דף מעוצב שנפתח בדפדפן ואפשר להדפיס / לשמור כ-PDF.
- **המסך עובר לשאלה החדשה, בלי קפיצות:** כל שאלה גולשת בעדינות לראש המסך והתשובה נכתבת מתחתיה. מתחת לשיחה שמור
  מקום, והתשובה מוצגת פעם אחת באותו מקום (בלי לצייר את הדף מחדש) - לכן אין "קפיצה" כשהתשובה נגמרת.
  נמדד בדפדפן: השאלה לא זזה אף פיקסל מרגע שהתשובה מתחילה ועד אחריה.
  בזמן הכתיבה רואים רק את השאלה החדשה והתשובה שנכתבת: Streamlit משאיר רכיבים של המסך הקודם "דהויים" עד שהם
  מוחלפים - הם מוסתרים, וכל הודעה מצוירת תמיד באותו מקום בדף כדי ששאלה חדשה לא "תירש" שאריות של תשובה קודמת.
- **אייקונים קוויים בכתום** (כמו באתר הפניקס) לנושאים, לשאלות לדוגמה ולשאלות ההמשך.
- **שאלות על הבוט עצמו** ("מה השם שלך", "מי כתב אותך", "אתה בוט?") - הסבר קצר מי הוא ומה אפשר לשאול.
- **"על מה יש לכם ביטוח?"** - רשימת כל המדורים באתר, מתוך האינדקס עצמו (חיפוש רגיל החזיר רשימה חלקית).
- **אף שאלה לא נשארת בלי תשובה:** אם הלקוח לוחץ על משהו בזמן שהתשובה נכתבת, השאלה נענית מיד אחרי.
- ציטוט של פחות מ-4 מילים ("ביטוח רכב") לא נחשב הוכחה, והבוט לא מתאר את המידע באתר ("בחלק מהעמודים יש רק כותרת").

### אבטחה
- **מפתחות:** ב-`.env` (לא ב-GitHub) או ב-Secrets של השרת. לא נשלחים לדפדפן.
- **הפרדה בין משתמשים:** כל חלון דפדפן מקבל session נפרד בשרת. שיחות לא נשמרות בשום מקום (לא קובץ ולא מסד נתונים),
  ולכן אין שיחה של משתמש אחד שמשתמש אחר יכול לראות. המשותף היחיד: מטמון של תשובות לשאלה ראשונה בשיחה - רק
  התשובה הכללית מהאתר, בלי שום דבר מהשיחה.
- **הזרקת הוראות (prompt injection):** שאלת הלקוח עטופה בתגית `<שאלה>` (והלקוח לא יכול לסגור אותה), וההוראות
  אומרות שזה טקסט ולא הוראות. גם אם המודל "ישתכנע" - אין לו כלים, סודות או מידע אישי, והקוד מאמת כל תשובה
  (מקור, מספרים, ציטוטים). הקישורים נבנים בקוד ולא על ידי המודל. נבדק ב-4 ניסיונות פריצה ב-`eval/dialogues.json`.
- **קוד בתשובה (XSS):** טקסט מהמודל ומהלקוח מוצג אחרי escape - תגית HTML מוצגת כטקסט ולא רצה.
- **ניצול המפתח:** שאלה עד 500 תווים, ועד 6 שאלות בדקה / 60 בשעה לכל חלון.

## מגבלות (סיכום)
- **רק מה שבאתר:** קובצי PDF (תנאי פוליסה, דוחות) ואזור אישי לא נכללים.
- **תלות בשירותים חיצוניים:** חיפוש = Gemini (וקטור לכל שאלה, מכסה חינמית של כ-1,000 ביום). תשובות = Claude, ו-Gemini כגיבוי. כשגם החיפוש וגם כל המודלים לא זמינים - הבוט מציג "השירות לא זמין" ומפנה לשירות הלקוחות.
- **סירוב לא מושלם:** ציון הדמיון לבדו לא מפריד בין שאלות עם ובלי תשובה; ההחלטה היא של מודל השפה, ובמקרי גבול (מידע קרוב לנושא) הוא עלול לענות.
- **מסלולים כמעט זהים** (96 עמודי מסלולי השקעה): בלי שם המסלול, הבוט מפרט אפשרויות או שואל שאלת הבהרה.
- **רענון בענן:** בשרת החינמי קבצים שנכתבו אחרי ההעלאה נמחקים כשהשרת מופעל מחדש. רענון מעמוד המנהל מחזיק עד
  ההפעלה הבאה; לעדכון קבוע מריצים `python ingest/index.py --refresh` ושומרים ל-GitHub. רענון מלא לוקח כ-40 דקות
  (הסורק ממתין בין עמודים כדי לא להעמיס על האתר).
- **מכ"ם הפערים והמשוב בענן** נשמרים באותו אופן - עד הפעלה מחדש של השרת (לשמירה קבועה: מסד נתונים כמו Supabase).
- **זמן תגובה בענן:** שאלה רגילה כ-3 שניות; שאלת המשך עד כ-10 שניות, כי מודל השפה "חושב" לפני שהוא עונה.
  נבדק: בלי שלב החשיבה התשובות מהירות יותר (חציון 2.6 שניות) אבל פחות מדויקות (ענה 35/40, סירב 19/20) - ולכן החשיבה נשארת.
- **שאלות הבדיקה** נכתבו בחלקן על ידי מודל שפה; שאלות אמיתיות של לקוחות עשויות להיות קשות יותר.
