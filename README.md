# בוט הפניקס - עוזר שירות לקוחות מבוסס RAG

בוט שעונה על שאלות לקוחות **רק** מתוך המידע שבאתר [fnx.co.il](https://www.fnx.co.il), עם קישור למקור בכל תשובה.

## מבנה הפרויקט
```
fnx-bot/
├── ingest/   "הכנת הספר" - איסוף, ניקוי וחיתוך המידע מהאתר
├── core/     "המוח" - חיפוש (retriever), ספקי מודל שפה (providers), שאלות גבול (guardrails), תשובה (answer)
├── eval/     בדיקות איכות על שאלות אמיתיות
├── data/     המידע שנאסף מהאתר
└── app.py    הממשק (הצ'אט)
```

## הפעלה

**פעם אחת:**
```
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```
יוצרים קובץ `.env` (לפי `.env.example`):
```
GEMINI_API_KEY=...       # חובה: הטמעות (חיפוש). גיבוי למודל השפה
ANTHROPIC_API_KEY=...    # מודל השפה הראשי (Claude). בלעדיו - Gemini בלבד
```

**בניית האינדקס** (פעם אחת, וכל רענון):
```
python ingest/index.py             # מהפסקאות הקיימות (data/chunks.jsonl)
python ingest/index.py --refresh   # רענון מלא: סריקת האתר -> חיתוך -> אינדקס
```

**הצ'אט:**
```
streamlit run app.py
```
נפתח בדפדפן: http://localhost:8501

**בדיקות:**
```
python eval/run_eval.py                           # הבוט כולו על 67 שאלות ותורות שיחה
python eval/run_eval.py --model claude-haiku-5-5  # מודל אחד בלבד
python eval/compare_search.py --questions eval/questions_full.json --formats search   # השוואת שיטות חיפוש
python eval/ping_models.py                        # זמני תגובה של כל מודל
```

## שלב 1: איסוף המידע מהאתר ✅

### איך מריצים
```
python ingest/crawl.py      # סריקה וניקוי  ->  data/pages.jsonl
python ingest/chunk.py      # חיתוך לפסקאות ->  data/chunks.jsonl
```
בדיקה מהירה על 10 עמודים בלבד: `python ingest/crawl.py --test 10`

### איך נאסף התוכן
1. **רשימת העמודים** נלקחת מה-[sitemap](https://www.fnx.co.il/sitemap.xml) של האתר, ומסוננת למדורים רלוונטיים (ביטוח, תביעות, שירות, פנסיה, גמל, חיסכון, הלוואות). מכבדים את [robots.txt](https://www.fnx.co.il/robots.txt).
2. **הורדה מנומסת:** בקשה כל 2 שניות. אחרי כ-1,000 בקשות ברצף האתר חוסם זמנית, ולכן יש ניסיונות חוזרים עם המתנה שגדלה, ומטמון שמאפשר להמשיך מאיפה שעצרנו.
3. **ניקוי:** כ-80% מכל עמוד הם תפריטים ופוטר. שומרים רק את אזור התוכן (`#main`), ומסירים אזורים חוזרים לפי ה-class שלהם.
4. **חיתוך לפסקאות** לפי כותרות, 120-400 מילים, עם כותרת הקשר (עמוד, מדור, נושא) בראש כל פסקה.

### מה יצא
| | מספר |
|---|---|
| עמודים ב-sitemap | 1,643 |
| עמודים רלוונטיים אחרי סינון | 1,035 |
| **עמודים ייחודיים שנשמרו** | **715** |
| **פסקאות** | **2,405** (מ-712 עמודים; 3 עמודים הם רק רשימות קישורים לדוחות PDF) |

### מה הוצא, ולמה
| קובץ | מה | למה |
|---|---|---|
| `data/not_found.txt` | 36 כתובות | מחזירות 404. רובן כתובות ישנות בעברית, שהתוכן שלהן קיים תחת כתובת באנגלית |
| `data/thin.txt` | 232 עמודים | כמעט בלי טקסט: רשימות של דוחות PDF, ומאמרים שנמחקו ומפנים לעמוד אינדקס |
| `data/duplicates.txt` | 52 עמודים | תוכן זהה לעמוד אחר (מאמר שנמחק מחזיר את עמוד המדור) |

### איך מרעננים
**מי מרענן:** מנהל המערכת, בלחיצה על כפתור "רענן עכשיו" (ייבנה בשלב האירוח). הכפתור מריץ פקודה אחת: `python ingest/index.py --refresh` = סריקה, חיתוך ובניית האינדקס (ראו שלב 2).

**איך יודעים מה השתנה:** לכל עמוד נשמר ה-ETag שלו, "טביעת אצבע" שהאתר מחשב מתוכן העמוד (`data/crawl_state.json`). בהרצה חוזרת שואלים את האתר "השתנה מאז?":
- **לא השתנה** – האתר עונה 304 בלי לשלוח את העמוד, ונשאר המידע הקיים.
- **השתנה או חדש** – מורידים ומנקים מחדש.
- **נמחק מהאתר** – מוסר.
- דוח שינויים (חדש / השתנה / הוסר) נכתב ל-`data/changes.json`.

למה לא תאריך העדכון ב-sitemap: בדקנו ומצאנו עמודים שהתוכן שלהם השתנה בלי שהתאריך זז (נתוני תשואות, טופס 161). ה-ETag כן משתנה בכל שינוי בתוכן.

**זמן:** כ-25 דקות לרענון (בעיקר ההמתנה המנומסת של 2 שניות בין בקשות). בבדיקה: 703 מתוך 715 עמודים ענו "לא השתנה", בלי חסימות.

**הגנות, כדי שרענון לא יקלקל מידע טוב:**
- **ירידה חדה:** אם יצאו פחות מ-90% מהעמודים של הפעם הקודמת (למשל כי האתר חסם), שום דבר לא נשמר והמידע הקודם נשאר.
- **הורדה שנכשלה:** נשארת הגרסה הקודמת של העמוד.
- **מילים מוסתרות (xxx):** סינון אינטרנט עלול להחליף מילים ב-xxx. עמוד כזה לא נשמר; נשארת הגרסה הנקייה הקודמת, והעמוד נרשם ב-`data/masked.txt`.

הרצה מלאה מאפס (מתעלמת מה-ETag): `python ingest/crawl.py --refresh-all`

### מגבלות
- **קובצי PDF** (תנאי פוליסה, דוחות) לא נכללים.
- **אזור אישי וטפסים** (my.fnx.co.il ואחרים) לא נסרקים. הבוט יכול רק לקשר אליהם.

## שלב 2: אינדקס סמנטי וחיפוש ✅

### איך מריצים
```
python ingest/index.py             # בונה את האינדקס  ->  data/index/
python ingest/index.py --refresh   # רענון מלא: סריקה -> חיתוך -> אינדקס
```
צריך `GEMINI_API_KEY` בקובץ `.env` (ראו `.env.example`).

### איך נבחר הקטע
1. **כל פסקה הופכת לווקטור** - רשימת מספרים שמייצגת את המשמעות שלה - עם המודל `gemini-embedding-2` של גוגל. לפני הפסקה מוסיפים את כותרת העמוד, כמו שגוגל ממליצה (`title: ... | text: ...`).
2. **גם שאלת הלקוח הופכת לווקטור** באותו מודל (`task: search result | query: ...`).
3. **מחשבים דמיון קוסינוס** בין השאלה לכל 2,405 הפסקאות (פחות מאלפית שנייה), ושולפים את **8 הפסקאות הקרובות ביותר**.
4. הווקטורים מקוצרים ל-768 מספרים (מתוך 3,072): בבדיקה האיכות זהה, והאינדקס קטן פי 4 (7.4MB).

### למה ככה - הבדיקה
השווינו שלוש שיטות על 154 שאלות בדיקה (`eval/compare_search.py`, `eval/questions_full.json`):
100 שאלות על עמודים שנבחרו בהגרלה (מודל שפה כתב שאלת לקוח לכל עמוד; נפסלו שאלות שמעתיקות מהעמוד),
15 על מסלולי השקעה כמעט זהים, 8 על שמות מוצרים, ו-31 שכתבנו ידנית.

העמוד הנכון בין 5 הפסקאות הראשונות:

| שיטה | אקראי | שמות | מסלולים | ידני | סה"כ |
|---|---|---|---|---|---|
| מילים (BM25 על שלישיות אותיות) | 73/100 | 8/8 | 15/15 | 19/31 | 115/154 |
| **וקטורים** | **87/100** | 7/8 | 15/15 | **31/31** | **140/154** |
| שילוב (מילים + וקטורים) | 85/100 | 8/8 | 15/15 | 27/31 | 135/154 |

**8 פסקאות ולא 5:** 5 הפסקאות הראשונות הגיעו בממוצע מ-3.5 עמודים בלבד (כמה פסקאות מאותו עמוד). עם 8 העמוד הנכון נמצא ב-91/100 מהשאלות האקראיות (144/154 בסה"כ). המספר 8 נקבע אחרי שראינו את התוצאות, ולכן ייבדק שוב על שאלות אמיתיות.

**מה עוד יצא בבדיקה:**
- רוב ה"פספוסים" בשאלות האקראיות הם עמוד אחר עם אותו מידע (למשל "עיכוב מזוודה" מביא את "המזוודה לא הגיעה").
- **שאלה בלי שם מסלול** ("מה דמי הניהול במסלול שלי?") - אף חיפוש לא יכול לדעת איזה מסלול. הבוט צריך לשאול את הלקוח.
- **ציון הדמיון לבדו לא מספיק כדי לסרב:** "באיזה בנק כדאי לקחת משכנתא?" (אין תשובה באתר) קיבלה ציון גבוה יותר מהרבה שאלות שיש עליהן תשובה. ההחלטה לסרב תהיה של שכבת התשובה.

### רענון
המטמון (`data/emb_cache/`) שומר וקטור לכל טקסט שכבר נשלח לגוגל. ברענון נשלחות לגוגל רק פסקאות חדשות או ששונו; פסקאות של עמודים שנמחקו פשוט לא נכנסות לאינדקס.

**הגנות - האינדקס הקודם נשאר כמו שהוא אם:**
- חסרים וקטורים (נגמרה המכסה, אין רשת). מריצים שוב, וההרצה ממשיכה מאיפה שעצרה.
- יש פחות מ-90% מהפסקאות של האינדקס הקודם.
- הסריקה או החיתוך נכשלו.

החיפוש בודק שקבצי האינדקס תואמים זה לזה (מספר שורות, מודל, טביעת אצבע של הווקטורים), ומסרב לעבוד עם אינדקס חלקי או פגום.

### מגבלות
- **מכסה חינמית של Gemini:** כל פסקה נספרת כבקשה, כ-100 בדקה וכ-1,000 ביום (נמדד). רענון רגיל עולה כמה עשרות בקשות; בנייה מחדש של כל 2,405 הפסקאות (למשל אחרי שינוי בכללי החיתוך) לוקחת כ-3 ימים בחינם.
- **כל שאלת לקוח היא בקשה לגוגל** (כחצי שנייה עד שנייה). כשהמכסה נגמרת או שאין רשת, החיפוש לא עובד.
- **עמודים דומים ממדורים שונים:** למשל "תביעת נזק מים" של ביטוח עסקים מופיעה לפני ביטוח דירה. הכותרת והמדור של כל פסקה נשלחים לשכבת התשובה כדי שתבחין ביניהם.

## שלב 3: שכבת התשובה ✅

### מה קורה בכל שאלה
1. **הודעת נימוס** ("תודה", "שלום") - תשובה ידידותית מיד. **בקשה לפרט אישי** ("מה מספר הפוליסה שלי") - הסבר שאין לבוט גישה, והפניה לשירות הלקוחות (`core/guardrails.py`).
2. **שאלת המשך** - מודל השפה מנסח אותה כשאלה מלאה לפני החיפוש ("ותוך כמה זמן?" -> "תוך כמה זמן מקבלים תשובה על תביעת נזילה בבית?").
3. **חיפוש** 8 הפסקאות הקרובות (שלב 2). אם גם הקרובה ביותר רחוקה מאוד (דמיון < 0.60) - "לא מצאתי" בלי לפנות למודל.
4. **מודל השפה** מקבל את השאלה ואת הפסקאות (עם כותרת ומדור), וכותב **מילה אחרי מילה** (streaming): שורת סטטוס (תשובה / לא נמצא / שאלת הבהרה), התשובה, ושורת מקורות עם מספרי הפסקאות.
5. **בדיקה בקוד:** הקישורים נבנים מהפסקאות עצמן (המודל לא כותב כתובות, ולכן לא יכול להמציא קישור). תשובה בלי מקור תקין מוחלפת ב"לא מצאתי" - **אין מקור, אין תשובה.**

**מה הבוט עונה כשאין מידע:** "לא מצאתי את המידע הזה באתר הפניקס. לבירור אפשר לפנות לשירות הלקוחות." + קישור לעמוד יצירת הקשר. ההוראה למודל: *עדיף לא לענות מאשר לענות תשובה לא נכונה* - מידע קרוב שלא עונה על השאלה עצמה, או בקשה להמלצה אישית, = "לא נמצא".

### מודל השפה, ולמה
המבנה מונחה עצמים (`core/providers.py`): מחלקה בסיסית `LLMProvider`, ומחלקה לכל ספק (`ClaudeProvider`, `GeminiProvider`). `FallbackProvider` עובר אוטומטית לספק הבא כשספק לא זמין. החלפת מודל או ספק = שורה אחת.

| סדר | מודל | למה |
|---|---|---|
| 1 | Claude Haiku 5.5 | יציב ומהיר: חציון 4.3 שניות, אף כישלון ב-65 בקשות. כעשירית סנט לשאלה |
| 2-4 | gemini-3.6-flash, gemini-3.1-flash-lite, gemini-flash-lite-latest | גיבוי. ה-API החינמי של Gemini החזיר הרבה פעמים 503 ("ביקוש גבוה") או לא ענה תוך 25 שניות; כל רגע מודל אחר זמין |

### תוצאות הבדיקה (`eval/run_eval.py`)
67 תורות: 40 שאלות עם תשובה (מדגם אקראי מ-`eval/questions_full.json`), 20 שאלות שאין עליהן תשובה באתר, ו-4 שיחות (שאלת המשך, החלפת נושא, שאלת הבהרה, פוליסה אישית).

| | Claude Haiku 5.5 (שפה זורמת) | Claude Haiku 5.5 (לפני) | Gemini (רשימה) |
|---|---|---|---|
| שאלות עם תשובה: ענה | 38/40 (*) | 40/40 | 39/40 |
| ...עם העמוד הצפוי כמקור | 34 | 35-36 | 35 |
| שאלות בלי תשובה: סירב | **20/20** | **20/20** | 17/20 |
| שיחות (14 תורות, כולל שיחת החתול ושיחה חופשית) | 14/14 | 14/14 | - |
| זמן עד סוף התשובה (חציון) | 5.2 שניות | 3.7 שניות | 8.1 שניות |

(*) שתי השאלות שסורבו (מחיר תור ב-A LIST, מסמכים לקצבת זקנה) נענו 3/3 בהרצה חוזרת - שונות אקראית של המודל, לא מידע חסר.

סגנון התשובות (אוקטובר 2026): כמו נציג שירות בשיחה - משפט פתיחה שעונה ישירות, 2-3 פסקאות קצרות בעברית יומיומית (בלי להעתיק ניסוח משפטי מהאתר), פנייה בלשון רבים, נקודות רק לרשימות ושלבים ממוספרים רק לתהליכים.
הפישוט הוא של הניסוח בלבד: כל עובדה חייבת להופיע באתר, ומה שלא כתוב במפורש - הבוט אומר שלא מופיע ומפנה לשירות הלקוחות, בלי להסיק מסקנות.
התשובות ארוכות יותר, ולכן הזמן עד סוף התשובה עלה; הטקסט מתחיל להופיע מיד.

בדיקת המספרים: כל מספר בתשובות של Claude (סכומים, טלפונים, אחוזים) הופיע בפסקאות שנשלחו אליו. ב"עמוד הצפוי" נבדק עמוד אחד מראש; ברוב ההפרשים המקור היה עמוד אחר עם אותו מידע.
הגרסה הסופית: `eval/results_answers_claude_v6_tone.jsonl`. גרסאות קודמות (לפני streaming והפרומפט המחמיר) באותה תיקייה.
שיחה אמיתית מהצ'אט: `eval/demo_conversations/cat.md`.
